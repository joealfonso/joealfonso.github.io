Designing AI-powered products

AI features at Amazon come with problems ordinary product work doesn’t have. The same input can give a different answer tomorrow. People decide how the whole feature works based on one interaction. And trust disappears the first time it confidently gets something wrong.

So I start with how it fails. For every AI feature I spend as long on what happens when the model is wrong, and how the screen recovers, as on the main flow. In HR that matters a lot: a misleading answer can affect someone’s pay, documents or start date.

Three rules I keep coming back to:

Show the evidence

Put the source next to the suggestion and let the person make the call

Design the fallback

When the model isn’t confident, the screen still has to work without it

Keep a person accountable

Someone has to be able to answer who approved what, and when

Building AI tools for design work

Alongside the product work, I build my own AI tools. It started because I wanted to know how these systems work from the inside. Now it’s part of how I work every day.

MCP servers

I’ve built several MCP (Model Context Protocol) servers that connect AI assistants to the things a designer actually uses: design systems, documentation, research repositories and project tracking. An assistant that can read the current design tokens, last week’s usability findings and the open tickets gives far better help than one guessing from a prompt.

LangGraph agents

I’ve used LangGraph to build research and synthesis agents that gather competitive information, find patterns across research sessions and draft structured design briefs. They don’t make design decisions. They shorten the gap between “we need to understand X” and “here’s what we know,” so the decision happens sooner and with better information.

Why this matters for product work

Building these tools changed how I design AI features. I’ve personally run into context-window limits, unreliable tool calls, hallucinations and slow responses. So when a product manager asks “can the AI just figure that out?”, I can give a straight answer and suggest a design that works with the real limits.

What I think about AI and design

The biggest change AI brings to design is speed. When you can prototype five directions in an afternoon, the slow part becomes deciding which one is right. That makes the old senior skills more valuable: asking the right question, knowing which signal to trust, and making a call when the data is unclear.

I’m not worried about AI making designers irrelevant. I’m more interested in what designers can do once they know how to use it well, and in designing AI products other people can use well.
